# Hiddify Bot

[![CI](https://github.com/getnull0/hiddify-bot/actions/workflows/ci.yml/badge.svg)](https://github.com/getnull0/hiddify-bot/actions/workflows/ci.yml)
![Python](https://img.shields.io/badge/python-3.12-blue)
![aiogram](https://img.shields.io/badge/aiogram-3.x-blue)
[![License: MIT](https://img.shields.io/badge/license-MIT-green)](LICENSE)

Telegram-бот для управления своей [Hiddify](https://github.com/hiddify/Hiddify-Panel) VPN-панелью. Вы поднимаете сервер, а раздаёте доступ родным и друзьям прямо из Telegram: без захода в веб-панель.

Два режима в одном боте: **админ** управляет пользователями и сервером, **пользователь** сам смотрит остаток трафика, берёт ссылку подписки и QR-код.

## Возможности

**Администратору**
- Пользователи: создание, правка, удаление, поиск по имени, UUID или Telegram ID, заметка, привязка Telegram ID.
- Трафик и срок: блокировка и разблокировка, сброс трафика, продление, лимиты, режим сброса (ежемесячно, еженедельно, ежедневно, без сброса).
- Статистика: кто онлайн, трафик за день, неделю и месяц с трендами, график за 30 дней.
- Сервер: CPU, RAM, диск, сеть, топ процессов, логи панели прямо в Telegram.
- Дополнительные серверы (узлы): статус, пинг, синхронизация, если они подключены к панели.

**Пользователю**
- Личный кабинет: остаток трафика и дней, когда сбросится трафик, когда был онлайн.
- Ссылка подписки и QR-код.
- Ссылки на приложения для всех платформ.
- Прокси для Telegram в одно нажатие, если админ включил его в панели.

## Быстрый старт

Понадобятся Docker (или Python 3.12), токен бота от [@BotFather](https://t.me/BotFather) и доступ администратора к панели Hiddify (проверено на v14.0.0b5, раньше работало на v11).

**1. Скачайте и настройте**

```bash
git clone https://github.com/getnull0/hiddify-bot.git
cd hiddify-bot
cp .env.example .env     # заполните значения, подсказки внутри файла
```

| Переменная | Откуда взять |
|---|---|
| `BOT_TOKEN` | токен от @BotFather |
| `ADMIN_IDS` | ваш Telegram ID (подскажет @userinfobot), несколько через запятую |
| `HIDDIFY_URL` | адрес панели с `https://`, без слеша в конце |
| `HIDDIFY_PROXY_PATH` | **админский** путь: первая часть админской ссылки `https://домен/<ПУТЬ>/<UUID>/admin/` |
| `HIDDIFY_ADMIN_UUID` | вторая часть той же ссылки |
| `HIDDIFY_USER_PATH` | **клиентский** путь: первая часть ссылки подписки любого пользователя `https://домен/<ПУТЬ>/<uuid>/` |
| `HIDDIFY_VERIFY_SSL` | `true`, если сертификат обычный; `false` для самоподписанного |
| `ADMIN_USERNAME`, `QR_API_URL` | необязательно: контакт поддержки и свой сервис QR-кодов |

Админский и клиентский пути в Hiddify разные, это самая частая ошибка.

**2. Проверьте панель до запуска**

```bash
docker compose build
docker compose run --rm bot python -m scripts.smoke --write
```

Скрипт проверит доступ, версию, пользователей, статус сервера и ссылку подписки, прогонит цикл на временном пользователе и **подскажет, какая переменная неверна**. Без `--write` он только читает.

**3. Запустите**

```bash
docker compose up -d --build
docker compose logs -f bot       # должно появиться «Hiddify panel OK» и «Bot started»
```

Откройте бота и отправьте `/start`. Админ видит в меню кнопку «⚙️ Админ-панель».

Без Docker: `pip install -r requirements.txt && python -m hiddify_bot`.

## Обновление

```bash
git pull
docker compose up -d --build
```

Бот не хранит данных (всё лежит в панели), поэтому обновлять и перезапускать можно в любой момент. Что менялось: [CHANGELOG.md](CHANGELOG.md).

## Если что-то не работает

| Что видите | Причина |
|---|---|
| «доступ запрещён» (403) | неверный `HIDDIFY_ADMIN_UUID` или админский путь |
| «invalid request» (400) | в `HIDDIFY_PROXY_PATH` стоит не админский путь |
| «не удалось подключиться к панели» | неверный `HIDDIFY_URL`; внутри Docker `localhost` не работает, нужен публичный адрес панели |
| ошибка сертификата | поставьте `HIDDIFY_VERIFY_SSL=false` |
| `smoke`: «HIDDIFY_USER_PATH неверный» | указан не клиентский путь |
| бот молчит на `/start` | неверный `ADMIN_IDS`, или тот же токен запущен ещё где-то («Conflict» в логе), или с сервера недоступен `api.telegram.org` |
| «Логи» и «Обновить трафик» дают 403 | этим админом нельзя: нужны права супер-админа |
| нет кнопки «Прокси для Telegram» | админ не включил Telegram-прокси в панели |

## Разработка

```bash
pip install -r requirements-dev.txt
make check          # то же, что проверяет CI: линтер, типы, мёртвый код, безопасность, тесты
```

Тесты не требуют ни `.env`, ни настоящей панели: в них поднимается фейковая панель Hiddify и фейковый Telegram. Подробности:

- [CONTRIBUTING.md](.github/CONTRIBUTING.md): как внести изменение
- [docs/architecture.md](docs/architecture.md): устройство бота
- [docs/hiddify-api.md](docs/hiddify-api.md): что бот берёт от API панели и подводные камни
- [docs/real-panel-testing.md](docs/real-panel-testing.md): как запустить настоящую панель для проверки
- [AGENTS.md](AGENTS.md): правила для AI-агентов

Об уязвимостях сообщайте по [SECURITY.md](.github/SECURITY.md).
